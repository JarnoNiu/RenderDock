RenderDock — небольшое нативное приложение macOS для тех, кто запускает рендеры из скриптов и терминала. Оно находит все задачи Blender, запущенные на машине без интерфейса, показывает, как далеко продвинулась каждая, и следит за железом, которое выполняет работу. Настройка не нужна, а сами задачи приложение никогда не трогает.

## Зачем

У рендера, запущенного из shell-скрипта, нет окна. В итоге приходится запускать `ps`, считать файлы в папке вывода и гадать, не уснул ли Mac час назад. RenderDock собирает всё это в одном месте, которое всегда на экране и никогда не мешает.

## Быстрый старт

Требования: macOS 14 или новее и тулчейн Swift 6 (Xcode 16+ или только Command Line Tools: `xcode-select --install`).

```bash
git clone https://github.com/JarnoNiu/RenderDock.git
cd RenderDock
zsh scripts/install.sh
```

Скрипт собирает приложение, копирует его в `/Applications/RenderDock.app` и запускает. Пароль администратора не нужен, скачивать зависимости не придётся. Добавьте `--login`, чтобы заодно включить запуск при входе.

Сейчас ничего не рендерится? Посмотрите на приложение с выдуманными задачами:

```bash
open -n /Applications/RenderDock.app --args --demo
```

Или посмотрите, как оно подхватывает настоящий процесс, без Blender и без GPU:

```bash
zsh scripts/fake-render.sh 60 1
```

> Готовой сборки для скачивания пока нет. Приложение не нотаризовано, а с неподписанной загрузкой хлопот больше, чем с 30-секундной сборкой. Подписанные релизы и Homebrew cask есть в планах.

## Как приложение находит ваши рендеры

RenderDock читает таблицу процессов и папки вывода. Приложение не встраивается в Blender, и менять скрипты не нужно.

| Что видит | Что показывает |
|---|---|
| Процесс Blender, запущенный с `-b` / `--background` | **Шот** |
| Самый внешний скрипт над ним в дереве процессов (`zsh render_all.sh`, `python queue.py`, …) | **Цепочка задач**: одна карточка. Название — первая строка комментария в этом скрипте |
| Аргументы `scene:shot` в командной строке скрипта очереди | **Очередь**: какие шоты готовы, какие рендерятся и какие идут следующими |
| Скрипт, обёрнутый в `caffeinate`, у которого ещё нет процесса рендера | **В очереди** |
| Процесс, остановленный через `kill -STOP` | **На паузе** |
| Нового кадра нет в 10 раз дольше обычного времени кадра (но не меньше 5 минут) | **Зависло** |
| Файлы изображений в папке вывода, без повторов по номеру кадра | **Готовые кадры**, секунды на кадр, миниатюра последнего кадра |

Папка вывода берётся из собственных параметров Blender `-o` / `--render-output` (включая пути с `//`, отсчитываемые от `.blend`) или из аргумента скрипта `--out ПАПКА` после `--`. Шаги вашего собственного пайплайна, которые не являются обычным рендером Blender, можно описать в небольшом [файле правил](../ADAPTERS.md).

### Откуда берётся процент

RenderDock показывает процент, только когда знает общее число. Приложение не гадает.

| Источник | Как показывается |
|---|---|
| `render-progress.json` в папке вывода (см. ниже) | точно: `412/720 frames · 57%` и оставшееся время |
| Диапазон кадров в командной строке: `-s 1 -e 250 -a` или `-f 1..250` | точно |
| Запуск через `renderdock run --` или с загруженным хуком Blender | точно, даже если в командной строке ничего не указано. Кроме того, отличает завершённую задачу от задачи, закончившейся ошибкой |
| Более старый клип с тем же именем рядом с папкой вывода | оценка с пометкой `≈`. Отбрасывается, как только число кадров её превысит |
| Ничего из этого | только число кадров и секунды на кадр, с неопределённым индикатором прогресса |

```bash
# точный прогресс без настройки
blender -b shot_010.blend -o //render/frame_#### -s 1 -e 250 -a
```

### `render-progress.json`: точный прогресс для любого пайплайна

Если диапазон хранится внутри `.blend` или ваш скрипт рендерит кадры сам, записывайте после каждого кадра один маленький файл в папку вывода:

```json
{"done": 12, "total": 720}
```

```python
# в Python-скрипте Blender
(out_dir / "render-progress.json").write_text(json.dumps({"done": i + 1, "total": len(frames)}))
```

Так может сообщать о прогрессе всё, что умеет записать файл, а не только Blender.

## Чего приложение не делает

- Оно **никогда не трогает ваши рендеры**: не посылает им сигналов и никогда не пишет в ваши папки с рендерами. Всё, что выходит за рамки наблюдения, выключено, пока вы сами это не включите: каналы уведомлений, локальный API (только `127.0.0.1`), Bluetooth для настольного дисплея, ответы на запросы агентов, вход для других программ и MQTT. Сетевых соединений не устанавливает, пока вы не добавите канал уведомлений или MQTT-брокер.
- Кнопок паузы, возобновления и остановки пока нет. Скрипты очередей часто сами управляют `STOP`/`CONT`, а две руки на одном выключателе — плохая идея.
- Если в командной строке нет ни папки вывода, ни диапазона кадров, задача всё равно появится, с CPU, памятью и прошедшим временем, но без кадров.
- Температура SoC читается с датчиков IOHID; это приватный интерфейс, доступный на Apple Silicon. На Mac с Intel или после обновления системы, которое переместит датчики, плитка показывает `–`. Скорость вентиляторов и потребляемая мощность не читаются.
- Собрано и протестировано на macOS 26 с M5 Max. Приложение компилируется под macOS 14, но на 14, 15 и на Mac с Intel не проверялось. Отчёты приветствуются.
- Языки интерфейса: английский и упрощённый китайский (выбирается по языку системы; принудительно задаётся через `--lang en` или `--lang zh`).

## Разработка

| Команда | Что делает |
|---|---|
| `zsh scripts/build-app.sh` | Собирает `build/RenderDock.app` (ad-hoc подпись; значок рисует само приложение) |
| `zsh scripts/install.sh [--login]` | Собирает, устанавливает в `/Applications`, перезапускает |
| `swift run rd-checks` | Проверяет ядро: парсинг, события, API, уведомления, агенты, протокол устройств (534 проверки) |
| `.build/release/RenderDock --dump` | Выводит найденные задачи и показатели текстом, без интерфейса |
| `.build/release/RenderDock --snapshot ПАПКА [--demo]` | Отрисовывает капсулу и панель в PNG |
| `zsh scripts/make-demo.sh` | Заново создаёт скриншоты и GIF в `assets/` |
| `zsh scripts/fake-render.sh [кадры] [сек/кадр]` | Имитация рендера для проверки обнаружения |
| `python3 scripts/verify-interactions.py <бинарник>` | Посылает клики и перетаскивания в экземпляр, запущенный с `--debug`, и проверяет раскрытие, сворачивание и прилипание (12 проверок) |

Код написан на обычных Swift и SwiftUI, окно сделано на AppKit: около 9000 строк, без пакетов. См. [CONTRIBUTING.md](../../CONTRIBUTING.md).

## Благодарности

RenderDock не использует код этих проектов, но они показали, что возможно без `sudo`: [Stats](https://github.com/exelban/stats) и [macmon](https://github.com/vladkens/macmon) — в чтении данных GPU и датчиков, [boring.notch](https://github.com/TheBoredTeam/boring.notch) — в том, как сделать маленький, всегда присутствующий интерфейс органичным для Mac.

Проект с похожей целью: [Blender Render Monitor](https://github.com/DUBSON0/blender-render-monitor) тоже показывает список рендеров Blender на Mac, и в нём уже есть пауза, возобновление и очередь. Прогресс он получает из hook-скрипта Blender или из лог-файла. RenderDock 0.1 был написан без знания о нём; общего кода у двух проектов нет.
