# 路线图与待办清单

[English](../../ROADMAP.md) · **简体中文**

渲染坞现在做到哪了、还缺什么、接下来做什么。最后更新：2026-11-26。

## 时间线

| 时间 | 版本 | 主题 | 状态 |
|---|---|---|---|
| 2026-11-23 | **0.1.0** | 首版：任务识别、悬浮胶囊、系统指标 | 已发布 |
| 2026-11-24 | **0.2.0** | 准确进度、通知、本机接口 | 已发布 |
| 2026-11-25 | **0.3.0** | 历史记录、coding agent、桌面小屏、不止 Blender | 已发布 |
| 2026-11-25／26 做完，早于原定目标（2027 年 2–3 月） | **0.4** | 桌面小屏分页并可走 Wi-Fi、从网络上访问、可选的控制、预览、浅色主题、刘海形态、桌面小组件 | 已做完，尚未发布 |
| 2027 年晚些时候 | **1.0 及以后** | 多台机器、新的界面形态、定制硬件 | 想法 |

日期是目标，不是承诺。0.2、0.3 和 0.4 都比原定的时间（12 月、1 月、2–3 月）提前做完了，但这不代表后面的也会提前。这是一个人的项目，优先级变了就更新这份文件，而不是悄悄放着不管。

0.3 在做的过程中变大了：原本排在后面的 coding agent 和桌面小屏加了进来。原定 0.3 的一项移了出去：局域网里访问接口，现在放到 0.4。

### 查过的和没查过的

在 macOS 26.6、M5 Max、三块屏上查过：对照真实的渲染队列核对识别结果；12 项交互检查；真实鼠标的拖动与吸附；安装并登记登录项；真实的 Blender 5.2 经包装命令和经钩子（命令行方式）渲染；每个推送渠道对着本机的替身服务核对请求；用 `curl` 测接口，包括它必须拒绝的那些请求。

还没查的：

- [ ] macOS 14 和 15（能按 14 编译，但没人在上面跑过）
- [ ] Intel Mac（预计温度那一格显示 `–`）
- [ ] 打开登录时启动后，真的注销再登录一次
- [ ] 运行中拔掉、再插上显示器
- [ ] macOS 通知横幅真的弹出来（要先有人点「允许通知」）
- [ ] 各推送渠道连真实的服务（本项目没有其中任何一家的账号）
- [ ] Blender 4.x：它的输出格式取自 Blender 源码，钩子也没在 4.x 上跑过
- [ ] 钩子作为插件在 Blender 窗口里使用

做完的标准：一周真实队列的预计完工时间和实际完工时间都有记录可查；有一种硬件能显示总进度，并在队列渲完时变化。

现在的情况：桌面小屏就是那一种硬件。历史从 2026-11-24 开始记，0.3 发布时还不满一周。后来还发现 0.3 只记了实际发生的事，没有记当时显示的预计值：预计值从 0.4 起才开始记（`renderdock estimates`），要等记满一周才有对照可看，这一条还欠着。

- [x] 浅色主题，以及跟随系统外观（默认仍是深色）。见 [外观与形态说明](../LOOKS.md)（英文）
- [x] 刘海形态：有事的时候刘海两边各伸出一截，点开后面板从屏幕顶边往下展开；没有刘海的屏幕上是顶边的一个小岛。看过图，也在一块真实的刘海上摆过位置；还没有长时间用过

## 硬件

道理很简单：应用现在有了本机接口，屏幕只是进度可以出现的地方之一。

| 档 | 是什么 | 需要 |
|---|---|---|
| 一、手头已有的东西 | 手机通知（0.2 已有）；像进度条一样逐渐填满的灯带和 Stream Deck 按键（0.3 的示例）；队列渲完时变色的智能灯（0.3 的 MQTT） | 0.2 的接口，或者 MQTT；从别的设备访问接口要等 0.4 |
| 二、开发板 | 桌上一块小触摸屏：瞄一眼看进度，按住按钮答复 agent | 低功耗蓝牙；固件开源，放在本仓库，目前支持一块板 |
| 三、专用设备 | 一份参考设计：屏、旋钮、灯环、一根线 | 只有第二档证明值得做才做 |

第二档已经有一块板可用，在 [firmware/desk-display](../../firmware/desk-display/README.md)（随 0.3 发布）。第三档还不存在。之后做什么都会公开设计，协议也会一直有文档，谁都可以自己做一个显示端。
