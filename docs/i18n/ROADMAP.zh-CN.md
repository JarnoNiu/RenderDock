渲染坞现在做到哪了、还缺什么、接下来做什么。最后更新：2026-11-24。

| 时间 | 版本 | 主题 | 状态 |

## 0.2 的现状

### 0.1 已完成

- [x] 从进程树里找出无界面的 Blender 任务，不用配置，也不用改脚本
- [x] 把各段归到最外层脚本名下成为一条任务链，卡片标题取脚本的第一行注释
- [x] 从 `scene:shot` 参数读出队列：渲完、在渲、暂停、待渲
- [x] 分得清进行中、已暂停（`SIGSTOP`）、可能卡住、排队等待
- [x] 已出帧数、每帧耗时、剩余时间、最新一帧的缩略图
- [x] 准确的总帧数：来自 `render-progress.json`，或 Blender 命令行里的帧范围（`-s -e -a`、`-f`）
- [x] 按旧片段估算的总帧数，一律标 `≈`
- [x] 不用 `sudo` 的系统指标：CPU、显卡占用、显存、内存与内存压力、交换区、芯片温度、磁盘剩余、电源、防睡眠
- [x] 悬浮胶囊：随处拖动，吸附到边、角和正中，记住位置，所有桌面可见，浮在全屏应用之上
- [x] 面板从胶囊所在的那个角展开；可固定；点别处自动收起
- [x] 带进度环的菜单栏图标
- [x] 「渲染时保持唤醒」（需手动打开）和「登录时启动」
- [x] 界面中英双语；README 十种语言
- [x] 演示模式、假渲染脚本、静态图渲染器、12 项自动交互检查

### 0.2 已完成

- [x] `renderdock run -- <命令>`：原样代跑命令，读渲染器自己的输出拿到准确进度，哪怕帧范围和输出目录都不在命令行里，见 [docs/EXACT-PROGRESS.md](../EXACT-PROGRESS.md)（英文）
- [x] Blender 钩子（一个 `--python` 脚本，同时也是插件），给没法包装的渲染用
- [x] 帧内进度：渲到一半的帧算半帧
- [x] 渲完还是失败：经包装的任务，退出码跟着 `job.ended` 事件一起给出
- [x] 在电脑上通知，需手动打开，见 [docs/NOTIFICATIONS.md](../NOTIFICATIONS.md)（英文）
- [x] 在手机上通知：Bark、ntfy、飞书、企业微信、钉钉、Telegram 或通用网络钩子，在你自己的设置文件里配
- [x] 本机只读接口（`127.0.0.1`）：`GET /v1/state`、事件流、`renderdock status --json`，见 [docs/API.md](../API.md)（英文）
- [x] 适配规则放进文件：流水线里不是普通 Blender 渲染的步骤，见 [docs/ADAPTERS.md](../ADAPTERS.md)（英文）
- [x] 扫描和界面拆开（`RenderDockCore`），并有 132 项检查：`swift run rd-checks`
- [x] 十种语言的 README 已更新

### 查过的和没查过的

在 macOS 26.6、M5 Max、三块屏上查过：对照真实的渲染队列核对识别结果；12 项交互检查；真实鼠标的拖动与吸附；安装并登记登录项；真实的 Blender 5.2 经包装命令和经钩子（命令行方式）渲染；每个推送渠道对着本机的替身服务核对请求；用 `curl` 测接口，包括它必须拒绝的那些请求。

还没查的：

- [ ] macOS 14 和 15（能按 14 编译，但没人在上面跑过）
- [ ] Intel Mac（预计温度那一格显示 `–`）
- [ ] 打开登录时启动后，真的注销再登录一次
- [ ] 运行中拔掉、再插上显示器
- [ ] macOS 通知横幅真的弹出来（要先有人点「允许通知」）
- [ ] 各推送渠道连真实的服务（本项目没有其中任何一家的账号）
- [ ] Blender 4.x：它的输出格式取自 Blender 源码，钩子也没在 4.x 上跑过
- [ ] 钩子作为插件在 Blender 窗口里使用

做完的标准：一周真实队列的预计完工时间和实际完工时间都有记录可查；有一种硬件能显示总进度，并在队列渲完时变化。

### 0.4：动手，但要小心 · 目标 2027 年 2–3 月

- [ ] 可选的控制，默认关闭：暂停、继续、降低优先级、一个渲完再起下一个
- [ ] 规则：用电池时暂停、电脑过热降速时暂停
- [ ] 看大图，拖动回看已渲的帧
- [ ] 风扇转速与功耗；每个任务耗了多少电
- [ ] 桌面显示原型：用现成的带屏带旋钮的开发板

做完的标准：控制项可以逐个打开，没打开就绝不动任何进程；原型能通过局域网或 USB 显示当前这一段和总进度，旋钮可以切换任务。

## 硬件

道理很简单：应用现在有了本机接口，屏幕只是进度可以出现的地方之一。

| 档 | 是什么 | 需要 |
|---|---|---|
| 一、手头已有的东西 | 手机通知（0.2 已有）；像进度条一样逐渐填满的灯带；Stream Deck 按键；队列渲完时变色的智能灯 | 0.2 的接口；MQTT 和局域网访问要等 0.3 |
| 二、开发板 | 桌上一块带旋钮的小圆屏：转一下切任务，瞄一眼看进度 | 走 USB 串口桥或 Wi-Fi 的接口；固件开源，放在本仓库 |
| 三、专用设备 | 一份参考设计：屏、旋钮、灯环、一根线 | 只有第二档证明值得做才做 |

第二、三档现在都还不存在。它们会公开设计，协议也会一直有文档，谁都可以自己做一个显示端。
